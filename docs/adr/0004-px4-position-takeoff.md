# ADR-0004：固定位置起飞与悬停后严格交接

- 状态：Accepted
- 日期：2026-11-01
- 关联：Issue #3；[ADR-0001](0001-runtime-validation-seam.md)

## 背景

原生 Ubuntu 的 20 个有界标定候选均未进入初扫。ROS 的微上升、地面证书、严格升级与软恢复同时参与 PX4 自带起飞坡道的爬升过程，使参考推进、积分恢复与跟踪保护互相制约。继续扩大标定网格不能代替控制职责的划分。

## 决策

在显式启用的 `px4_takeoff_enabled` 路径中，保留顶层任务阶段，将 SAFE_TAKEOFF 内部改为固定位置目标，由 PX4 原位置环和起飞坡道爬升。心跳与目标仍由独立 50 Hz 发布线程拥有；速度、加速度与偏航速率为 NaN，不假造轨迹前馈。

起飞前验证已确认柱体、资产与机体审计；爬升期间仅监督漂移、倾角、导航与飞控状态、超高和固定期限。违规请求 NAV_LAND，交由 PX4 降落。该路径不使用地面/过渡证书、A–D 策略、微上升、恢复次数或外部积分标定；旧实现暂保留在关闭开关的路径。硬件默认关闭新路径。

满足新鲜离地、到高、低速及持续悬停后，以实际状态重新锚定严格执行器。第一个独立、有效的严格 HOLD 确认前保持 SAFE_TAKEOFF；确认后才进入 HOVER_SCAN。初扫及后续阶段继续原安全域与跟踪策略，地图未知不能成为巡航通路。

## 取舍与验证边界

爬升期不提供逐帧地图避障或备用停止保证，依赖事先静态证明与漂移监督。它不能自动适用于未审计环境或实机。固定超时不会因重规划、状态变化或交接重新计时。时钟回退、坐标 epoch 变化仍执行既有 P0 处理。

runtime 负责运动、监督与交接；validation 仅选择隔离配置、注入控制端观测、记录真值和独立判定。真实 `powerplant.sdf`、默认 PX4 参数、连续三次到高交接及漂移/超时降落证据是本轮验收目标；起飞成功不代表初扫完成或主链通过。
