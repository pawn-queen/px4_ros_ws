## 1. 建议先做什么

当前项目已经具备自主探索的基本闭环。下一步应按以下依赖关系推进：

1. **P0：先保证输入、地图和任务状态可信。** 补齐定位质量与时钟检查、全阶段健康监督、起飞空间约束和真实落地确认；恢复跨进程 ROS 联调，建立可重放基线。
2. **P1：提高现有建图与前沿规划的效率和观测有效性。** 精确体素遍历、深度自适应采样、增量膨胀/前沿更新、实际相机视场、转向与停留耗时、覆盖驱动初扫，以及有原因分类的重规划。
3. **P2：把几何路径升级为可执行、可制动的轨迹。** 引入速度/加速度约束与已知空闲区内的备用停止轨迹；增加房间—门洞级全局引导，以及目标表面覆盖和照片质量评估。
4. **P3：在真实数据支持下增加定位感知与动态环境能力。** 建立 UWB 质量空间模型，按传感器条件评估 VIO 特征感知；加入动态障碍跟踪、预测与经过标定的能耗模型。

保留已有主链：

```text
START → SAFE_TAKEOFF → HOVER_SCAN → EXPLORE
                                      ↓ 目标确认
                                TARGETING_CYCLE
                                      ↓
                                 RETURN_HOME → LANDING
```

巡检后是否继续探索由剩余预算和任务策略决定。没有发现目标也可以结束探索并返航。所有实际飞行路径继续要求具备**已验证安全空间**的证据：通常来自实际观测空闲体素，起飞及有限衔接可使用独立确认柱体；未知空间只用于信息收益和探索方向推断，不能直接飞入。

这份建议特别延续此前约束：安全起飞后稳定悬停，雷达观察水平轮廓，前向深度相机通过**缓慢偏航**观察不同方向；必要时只在已确认安全的小范围内平移，不以大幅横滚、俯仰来获得地图。

### 3.1 当前观察点评分的具体含义

默认参数下，可将最终评分写成：

```text
score = 3 log(1 + N_unknown) + 2 log(1 + G_surface)
        - 0.12 (T_out + T_home) + 0.5 clearance
        - 0.5 variance × (1 + T_out + T_home)
        + 0.5 margin / max(T_remaining, 1)
```

`T_out`、`T_home` 来自路径长度除以配置速度；`margin` 扣除了返航和预留时间。评分前已经存在可达性、定位方差、预算等硬约束。见 [评分实现](src/frontier_planner.cpp#L455) 和 [默认配置](include/px4_powerplant_mission_cpp/core.hpp#L117)。

需要优化的重点是各项估计的真实性：

- 时间尚未完整计入转向、加减速、停留采图、目标确认和拍照。
- 定位预测是当前 XY 方差加“到当前位置的欧氏距离 × 增长系数”，不是沿整条路线传播的状态协方差，也不是由真实 UWB 锚点质量构建的地图。
- FOV 默认值、候选数量、偏航离散数及多项权重仍在核心配置中，`config()` 只从 ROS 参数传入其中一部分。调参前应先明确哪些参数实际生效，见 [mission_planning.cpp](src/mission_planning.cpp#L3)。

## 5. 建图优化：先提高证据质量，再提高更新效率

### 5.1 位姿插值之后，还需要质量与坐标系一致性

现有按时间插值已经解决了“用最近收到的位姿投影”的主要问题，不应重新描述为尚未实现。下一步建议：

1. `StampedPose` 携带位置/姿态协方差、状态有效性和估计器重置标识。mapper 对位置、yaw 以及 roll/pitch 都进行质量检查；拒绝位姿不确定性过大的投影，避免仅凭时间戳有效就累积进静态地图。
2. 区分普通网络乱序、ROS 时钟回退、PX4 估计器 reset 和坐标对齐变更。当前“大幅旧时间戳触发清空”可作为保守保护，但不能长期代替明确的时钟/估计器状态协议。
3. 引入 `pose_epoch/map_epoch`。如果位置或航向发生不连续重置，而又没有可靠的新旧地图变换，停止拼接旧地图与新观测；规划任务、目标坐标和返航坐标也必须检查 epoch。只清空 mapper 而让控制器继续使用旧 home，仍会造成坐标不一致。
4. 记录原始采样时间、接收时间、排队时间和插值区间。用插值间隔与运动速度/角速度共同限制允许误差，不能只通过扩大 250 ms 阈值来“减少丢帧”。

**工程推断：**在现有 UWB 健康下降会反映到导航协方差的情况下，mapper 没有位置方差门控，可能将明显变差的位置继续用于建图。这比换一种插值曲线更应先处理。冻结坏数据的地图积分不等于可以继续按旧地图飞行，还需要第 8 节的全阶段健康监督。

### 5.2 完整外参和明确的传感器逆模型

建议用统一变换表达传感器点：

```text
p_map = T_map_body(t_sample) × T_body_sensor × p_sensor
```

`T_body_sensor` 应包含实测旋转和平移。深度相机光学坐标约定、雷达安装角、机体坐标与地图 ENU 不能只靠固定轴交换隐式处理。若之后接入三维 LiDAR，还需驱动提供的逐点时间和运动去畸变；当前 LaserScan 逐束补偿不能被表述为已支持所有三维点云去畸变。

测距输入至少区分三类：

| 类型 | 建议地图更新 |
| --- | --- |
| 有效命中 | 射线前段贡献空闲证据，终点贡献占据证据，并按距离/噪声调整可信度 |
| 驱动明确表示可信的量程内无回波 | 在传感器可验证的范围内贡献空闲证据，不制造终点障碍 |
| NaN、失效、过曝、玻璃反射或语义不明的超量程值 | 保持未知/不确定，不因“没有点”就清空空间 |

上述无回波行为必须先核实具体硬件驱动的约定。深度与雷达也不必共享相同的 `hit/miss` 强度：记录来源、时间和不确定性，避免重复相关观测无限增强置信度。水平二维雷达只能支持被实际射线观测到的高度附近，不能据此把上下空间都判为空闲。

### 5.3 精确射线遍历与薄障碍观测

采用 R1 的体素边界遍历思路，替换固定步长采样，保留现有批次去重和“命中优先”语义。[R1：原始算法](https://doi.org/10.2312/egtp.19871000)

具体实现应明确射线刚好落在面、棱、角上的规则。**碰撞检查的保守 supercover 与地图空闲更新不是同一种证据语义**：碰撞检查可以扩大覆盖集合；一条零宽射线仅擦过一个体素角点，不足以证明整格没有障碍。因此不能把保守碰撞遍历集合直接用于更激进的清空。

当前 [共享 YAML](../px4_powerplant_mission/config/powerplant.yaml#L116) 中深度采样步长为 16 像素。用示例焦距 `fx=430` 估算，在 18 m 处相邻采样射线的横向间隔约为 `18×16/430≈0.67 m`。这是投影几何估算，不是相机的实际检测分辨率；它提示细管、电缆和门框可能在采样间隙被遗漏。提高体素分辨率本身不能补回未采到的障碍。

建议按距离、深度突变边缘和当前飞行走廊自适应采样：近处通行区域、门洞边缘和疑似细障碍加密，远处平面适度稀疏。验证时同时统计薄障碍召回、错误空闲和计算开销，防止只追求点数或地图外观。

### 5.4 局部有界地图、增量膨胀和全局返航记忆

ROG-Map 的机器人中心有界结构和增量膨胀适合降低重复工作；Voxblox 和 nvblox 分别提供 CPU/GPU 距离场路线。[R3](https://arxiv.org/abs/2302.14819)、[R2](https://arxiv.org/abs/1611.03631)、[R4](https://arxiv.org/abs/2311.00626)

对本项目建议分两步，而非一次替换整个地图：

- **第一步：**保留稀疏占据地图，输出本次状态变化的体素集合；对局部膨胀、前沿和碰撞缓存做增量更新。先测量是否已满足控制时限。
- **第二步：**若规模增长仍成为瓶颈，建立高分辨率局部滚动地图和较低分辨率全局占据/连通图。局部层用于飞行与制动，全局层保留门洞连通关系、home 和已验证返航走廊。局部移出窗口不应等于整个系统“忘记返航路”。

是否增加 ESDF 由规划需求决定：大量净空查询、连续优化可能受益；如果选用 EGO 类局部规划，不必先实现完整全局 ESDF。无论哪种方案，**距离值为正都不能替代已知空闲掩码**，未观测区域仍禁止成为执行路径。

通信上也应避免每次复制整张地图。可以新增有版本的增量协议：`map_epoch、base_revision、revision、changed_cells`，保留全量快照用于启动和断流恢复。消费者发现缺失增量或 epoch 不符时等待重同步，不能自行假设缺失部分为空闲。原有完整性检查应保留到新协议通过故障注入验证之后。

### 5.5 动态障碍层和地图老化

R11 展示了 RGB-D 检测、时序跟踪和运动预测的无人机应用，可作为动态处理的起点。[R11](https://arxiv.org/abs/2209.08258)

建议静态结构层保存墙体、管线等长期证据；短期动态层保存人员/移动物体的状态、时间与不确定性，局部规划同时检查两层。初期可用连续帧几何变化与简单跟踪实现，不必先训练新的语义网络。

不能用“障碍超过若干秒未见就变空闲”解决拖影：过时占据证据应降为未知/待重新观测，直到有新的可信射线证明空闲。历史空闲也有有效期，特别是门洞和人员活动区域；返航前需要重新确认。对于前向相机看不到的后方，动态模型应增加不确定性，而非把旧预测当成精确障碍位置。

## 6. 前沿与观察点评分：从局部贪心走向有记忆的探索

### 6.1 增量前沿簇优先于全量调大候选数

FUEL 的增量前沿结构直接对应当前“每次从全量空闲集合重新找边界”的开销。[R5](https://arxiv.org/abs/2010.11561)

建议由变化体素及其邻域触发前沿新增、删除、分裂与合并；为前沿簇维护边界范围、法向估计、候选观察点和可达性。观察点继续从有足够三维净空的已知空闲侧产生，不把前沿体素本身当成必飞航点。

缓存需要有失效依据：障碍变化会使路径成本和连通性失效，新增未知可见区域会改变收益。先引入可审计的缓存失效规则，再追求更复杂的增量最短路；不能只复用旧路径长度而不复查障碍。当前探索需要同时估计多个候选的去返距离，共享距离树仍有价值；固定单目标返航/巡检可以另行比较 A*，不必把所有 Dijkstra 调用统一替换成逐候选 A*。

### 6.2 多房间采用拓扑引导，仍只执行局部安全段

FALCON 用连通性和全局覆盖引导减少重复访问，特别适合本项目之后面对房间、门洞和长走廊的情况。[R6](https://arxiv.org/abs/2407.00577)

本项目可把“已探索房间/连通区域—门洞—待探索边界”构成图，先选择区域，再在该区域选择观察点。当前搜索半径内没有候选，应尝试向已知可达的远端前沿移动，而不是立即等同于全图探索结束。全局未知区域可用于排序假设，但局部执行仍要求最新地图上的已知空闲路径与返航可达性。

建议给规划失败返回明确原因：`WAITING_FOR_MAP`、`NO_LOCAL_CANDIDATE`、`FRONTIER_EXHAUSTED`、`BLOCKED`、`LOCALIZATION_POOR`、`RETURN_RESERVE_LOW`、`CANCELLED`。这些是建议的新接口，并非现有状态。只有证据支持全局已完成时，才能报告完成；局部范围不足、质量退化和预算不足应有各自的退出原因。

### 6.3 评分先校准观测与时间，再增加复杂模型

建议保留“硬约束筛选 + 候选效用排序”，逐步替换粗略估计：

- **真实可见性：**用 CameraInfo/标定得到实际 FOV、畸变处理后的有效区域、工作距离和朝向。保留遮挡判断；将无法可靠返回深度的材料/距离降权。
- **新增信息：**先用覆盖去重和历史实际收益校准当前未知计数，再考虑带占据概率与测量模型的期望熵下降。不能把被第一个未知格挡住的所有后方体素一次算作确定收益。
- **时间：**计入偏航时间、速度变化、稳定停留、采图/确认时间和返航降落准备。偏航所需时间至少受 `abs(wrap(Δyaw))/yaw_rate_limit` 约束；平移与转动能否并行要由轨迹与视场限制决定，不能统一简单相加或全部忽略。
- **表面补拍：**从“目标中心的缺照数”升级为可见表面、角度覆盖和图像质量的增量，见第 8 节。
- **定位与余量：**定位阈值、三维净空、去返可达性和最低剩余预算作为硬门槛；较高收益不能抵消这些门槛。

一种待验证的工程效用形式是：

```text
在可执行、可停止、可返航、定位满足阈值的候选集合中：
U(view) = wI × normalized(expected_information_gain)
        + wS × normalized(new_qualified_surface_coverage)
        - wT × normalized(total_time)
        - wR × normalized(residual_risk)
        - wE × normalized(energy)
```

这不是某篇论文给出的本项目最优公式。归一化范围、权重和风险估计需要由场景数据校准；能耗没有实测模型时先继续使用保守时间预算，不制造虚假的精确电量预测。

### 6.4 记住“从哪里、朝哪里、实际看到了什么”

当前 `visited_` 主要记体素位置，同一位置不同方向可能有完全不同的信息价值。建议记录 `(position_region, yaw_sector, map_epoch, observation_revision)`，以及实际新增空闲/占据体素和合格表面覆盖。视点“到达”与“取得有效观测”分开统计。

对无效观察设置可恢复的冷却机制：深度暂时失效、目标被人遮挡、门后来打开，应允许重新评估；不要永久禁用整个位置。有效重访可以是原地转向，不必为了新的位置编号而增加飞行距离。

### 6.5 减少异步规划结果持续作废

当前任何全局观测版本改变都可能使正在计算的探索结果失效。地图更新较快、规划较慢时，可能长期得不到可执行结果。建议记录规划依赖的前沿区域、局部走廊和返航走廊，用变化区域判断哪些部分需要重算。

采用该优化前必须保留三道检查：**地图 epoch 一致、最新局部轨迹仍安全、最新返航路径/预算仍成立**。远处小变化可以只重估收益；局部障碍、坐标重置或返航断连必须拒绝旧结果。这比单纯取消版本检查更可靠。

## 7. 局部路径：从“连得通”升级为“飞得稳且停得住”

### 7.1 几何路径和动力学轨迹分层

现有六邻域路径适合作为保守骨架，但转角多，setpoint slew 主要限制速度与偏航变化，并不完整约束加速度、jerk 或停止距离。建议先在已知空闲中进行可验证的捷径化，再增加带时间参数的局部曲线；平滑后的曲线也必须重新检查，不能仅检查原始折线或控制点。

可对比两条实现路线：

| 路线 | 适合条件 | 需保留的额外工作 |
| --- | --- | --- |
| 占据地图 + 引导路径 + EGO 类局部优化 | 希望控制内存/距离场维护成本，先改善局部运动 | 仍需独立的已知空闲检查、时间约束、备用停止与 PX4 跟踪验证 |
| 局部 ESDF/安全走廊 + 受约束轨迹优化 | 有较多净空查询，需连续几何余量和多目标优化 | 控制距离场更新延迟、走廊保守性和求解失败处理 |

R7 提供第一类局部优化参考；R8 提醒轨迹与偏航应帮助传感器提前看到潜在障碍。应通过相同地图、控制器和计算平台的实验选路线，不必同时引入全部框架。[R7](https://arxiv.org/abs/2008.08835)、[R8](https://arxiv.org/abs/2007.03465)

### 7.2 净空应包含机体、误差和停止空间

当前固定净空半径还不能代表实机所有安全余量。建议分开计算静态几何膨胀与前向制动要求，例如：

```text
r_geometry = r_body + epsilon_map + epsilon_tracking
             + k_sigma × sqrt(lambda_max(Sigma_position))

d_free_along_motion ≥ v × tau_total + v² / (2 × a_brake_min) + epsilon_stop
```

其中 `tau_total` 包含采样、传输、建图、规划、控制响应；`a_brake_min` 来自本机在相关载荷和姿态约束下测得的可保证减速度。机体姿态变化、体素离散误差和障碍运动还需单独纳入模型。上述公式是**静态障碍、简化运动假设下的工程设计起点**，不是通用安全证明；协方差未校准时也不能把 `k_sigma` 解释为已保证的碰撞概率。

这说明局部路径长度应随速度、可见距离和停止能力调整。当前固定 2 m 局部段在某些速度/延迟下可能太短，在狭窄低速场景又可能不必走满。优化目标应是增加安全有效观测，而不是单独提高巡航速度。

### 7.3 始终保留能在已知空闲区结束的备用轨迹

FASTER 的关键借鉴是持续维护已知空闲空间中的备用轨迹；SUPER 则提供了感知、规划和机体性能共同约束的系统案例。[R9](https://arxiv.org/abs/2001.04420)、[R10](https://github.com/hku-mars/SUPER)

对本项目建议：每段执行轨迹都附带制动/安全停留方案，下一段只有在当前状态可接入、空间仍有效、时限内能完成时才替换。新障碍或求解超时出现，选择经过验证的备用动作。“发布当前位置作为悬停点”并不自动满足这一条件，尤其是飞机已有速度时。

备用轨迹还依赖可靠状态估计。定位彻底失效时，不能继续以旧位置宣称安全悬停，应进入经过实际 PX4 配置和飞行验证的降级流程。本文不替用户确定未经标定的 failsafe 模式或高度。

## 8. 任务流程优化：保留主状态机，补齐每阶段的条件

### 8.1 全阶段健康监督先于新规划算法

[offboard_node.cpp](src/offboard_node.cpp#L79) 当前部分新鲜度使用接收时刻；收到延迟旧包时可能被误认为最新。mapper 与控制器的时钟使用也并不完全相同。建议同时检查采样时间和到达间隔，并明确时间域；不能直接相减仿真时间、设备时间和墙钟时间。

[safety_required()](src/offboard_control.cpp#L157) 主要覆盖探索、巡检、返航地图/路径条件；启动和探索有定位检查，但这不等于所有阶段的运动发布前都完成持续定位检查。建议统一健康监督，检查时间重复/倒退、坐标系、位置/姿态质量、传感器与地图新鲜度、飞控状态和预算，在每次允许运动前生效。

健康监督应区分：仅地图暂时过期但定位可靠，可以按已验证制动策略停下；定位本身不可用，应进入另行验证的飞控降级策略。两种故障不能都用旧地图中的“当前位置悬停”处理。

### 8.2 各阶段具体修改方向

| 阶段 | 现有基础 | 建议下一步及验收条件 |
| --- | --- | --- |
| START | 定位、倾角、预检、Offboard 预热与解锁门控 | 加入时钟/epoch、实际标定和健康检查；保存同一坐标系下的起飞点、地面高度和起飞区域；反复收到旧包不能通过新鲜度检查 |
| SAFE_TAKEOFF | 向配置高度上升并稳定 | 起飞高度改为明确相对起飞地面/平台的定义；验证机体扫掠柱体与顶部净空。无向上传感器、初始地图不足时必须依赖事先确认的安全起飞区，不能通过人为填空闲球“证明安全” |
| HOVER_SCAN | 稳定、低倾角、低速度、慢偏航，累计实际融合数据 | 以有效角度覆盖和首段运动/制动所需空闲体积作为退出条件；保留超时与健康检查。无可靠深度时停留或退出，不强行进入探索 |
| EXPLORE | 已知空闲视点、局部段执行、新观测重规划 | 增量前沿、全局区域引导、真实时间代价、失败原因分类；姿态/位置变化后重新核算可见性和备用停止空间 |
| TARGETING_CYCLE | YOLO 触发、巡检点路径规划、异步拍照 | 先完成目标确认与空间关联，再进行表面视点规划；照片质量达标才计入覆盖。目标丢失可有限重观察，预算不足应返航 |
| RETURN_HOME | 已知空闲返航，无路时等待 | 在执行中持续检查返航通道和剩余预算；预留已验证备用停留/降落位置。历史走过的路仍需检查当前障碍，不能盲飞旧轨迹 |
| LANDING | 发送降落命令；当前按绝对高度或超时进入 COMPLETE | 加入飞控实际落地/解锁状态确认；落地高度与起飞平台一致。超时应报告未确认/失败，不能按任务成功结束 |

起飞阶段的关键物理限制是：**前向深度相机加水平雷达不能完整证明头顶安全。** 没有初始体素地图并不要求大倾角扫描，而是要求把起飞区作为已确认前提，然后用稳定观测逐步扩展可飞区域。

### 8.3 初扫从“固定次数”变成“有证据的覆盖”

当前初扫已经有实际融合计数和稳定门控；问题是固定方向/次数不完全等价于每个方向取得了有效、同步的空间观测。建议记录每帧在采样时刻的 yaw、有效深度覆盖率、量程、姿态和采样 ID；同一旧帧不能重复满足多个方向。

维护水平角度扇区与三维已知空闲体积。优先补扫尚未观测的方向，再判断是否存在一条可安全执行和停止的首段路径。不是必须每次机械地转满一圈，也不能仅因雷达水平轮廓闭合就认为机体上下净空足够。

小范围自主巡查可作为增强：只有机体包络和备用停止空间都已经确认安全时，才做短距离侧向/前向移动以消除遮挡。若连这样的空间都没有确认，则继续原地观测或结束任务，不通过姿态激烈变化“探路”。

### 8.4 YOLO 确认与表面覆盖应分开

当前检测可较快触发目标状态，三维目标估计使用检测框、深度及位姿信息。优先改进 RGB 与注册深度的采样匹配、内参/尺寸对应和采样时刻位姿，再做多帧三维关联。`candidate → confirmed → inspecting → completed/lost` 可作为目标子状态；这里只是建议，不改变主任务链。

目标中心不是表面模型。R12 的探索后巡检组织与 R13 的全局覆盖/局部适配为此提供参考；R13 依赖参考地图，其实机证据也不能直接推广为无先验、动态人群中的完整验证。[R12](https://doi.org/10.1016/j.autcon.2023.104753)、[R13](https://arxiv.org/html/2504.09294v1)

本项目可在已构建局部地图上提取目标表面片，候选视点评估：可见面积、遮挡、入射角、距离/成像尺度、与已有照片的互补角度，以及路径和返航代价。先对已确认目标做局部覆盖，不必立即建设全场景高精度网格模型。

目前固定圆周/固定高度/固定照片数在狭窄室内可能不可达，拍足四张也不等于覆盖完整。建议只有图像时间新鲜、目标确实可见、清晰度/曝光符合任务要求且写盘成功，才更新“合格覆盖”。保留异步写盘架构，但将允许无图记录的 fallback 与实机任务成功判定分开，见 [inspection_recorder.cpp](src/inspection_recorder.cpp)。

### 8.5 返航预算覆盖整个任务

现有按路径时间和 PX4 剩余飞行时间估计预算是合理起点。应将巡检停留、目标重确认、规划等待、制动与降落准备纳入所有阶段的预算监督；不能只在 EXPLORE 决策时检查。

返航通道被堵时，保持在可验证安全空间内重新观测/规划，并对等待设置与电量相关的限度。备用降落点必须经过几何、地面和任务约束验证，不能将任意已知空闲体素当成可落地点。后续只有采集实际功耗与飞行日志后，再用能耗模型替换部分固定时间裕量。

**2026-10-26 执行进展：**P0、P1 七项以及 P2-A/B/C 核心均已有实现；P2 采用保守五次直线段并停稳转弯，不引入优化求解器。上表保留调研时建议，当前原理和差异见 [P2_IMPLEMENTATION.md](P2_IMPLEMENTATION.md)。正在完成 P2 的系统验收；任意硬件外参、驱动无回波语义、原始传感器负载下的尾延迟及真实制动能力仍须相应证据。下一步先解决真实闭环暴露的问题并完成可重放飞行验证，再扩大速度和室内实机任务范围。

**2026-10-28 范围补充：**“全局区域引导”指在完整已知安全连通空间中组织航路，不表示必须执行全电厂任务。当前任务 ROI 默认 x=[-24,34]、y=[-9,49]、z=[3.5,7] m；只对其中未知区域和巡检表面计算任务收益。起飞、初扫、接入、绕障、外侧观察位及返航按完整导航证据验证。没有可用 ROI 工作视点时，接入候选限定为 home 与 ROI 联合 AABB 外扩 10 m，默认累计 60 s，重访代价 5 s；无可达入口、仍有未知或超预算必须明确报告，不能改写为全场完成。ROI 参数仅 IDLE 接受有效原子修改，迟到结果按独立版本失效。

这些优化应进入同一套 C++ 核心，由仿真/实机配置选择传感器参数、外参和时钟；不另复制一套硬件专用规划算法。原 Python 参考可用于对照，但新功能若有意改变算法，应记录预期差异，而非继续要求所有新结果与旧算法完全相同。

### 9.2 评测场景与指标

正式仿真固定为实际 `powerplant.sdf` 电厂及锁定后的碰撞资产；回归小房间只验证算法和故障，不替代该场景。`run_acceptance.py --scenario powerplant` 分别提供起飞初扫、ROI 接入进展和完整局部任务范围，有限阶段和准备脚本均不能计为完整飞行或巡检通过。几何真值、临时物理探针及标注数据只用于独立评估，不作为在线规划地图或预知航点。

建议保存固定地图、随机种子、传感器模型、控制器参数、任务条件和计算平台，比较 B0 当前基线与逐项改进。仿真可先每个场景重复 20 个种子，再依据方差和成本扩展；这是本项目建议的实验设计，不是文献已证明足够的样本量。

| 场景/故障 | 应观测的结果 |
| --- | --- |
| 低顶棚、起飞平台高度变化 | 不穿越未验证起飞柱体；高度定义一致；不因超时误判落地 |
| 窄门、细管、电缆、斜墙和体素边角 | 障碍召回、错误清空、连续机体最小间距、碰撞/未知侵入次数 |
| 多房间、回字走廊、局部范围内无前沿 | 全局覆盖、重复路程、规划失败原因、是否过早返航 |
| 弱纹理、玻璃/反光、深度掉帧 | 地图伪影、未知保留、有效视点收益；无测量是否被错误当空闲 |
| UWB NLOS/锚点失联、估计器 reset、乱序旧包 | 质量门控、epoch 一致性、恢复时间、停止/降级动作是否符合设计 |
| 行人横穿、门关闭、返航堵塞 | 动态避碰、制动裕量、重新确认、等待预算及返航结果 |
| YOLO 误检/目标丢失、旧图像、磁盘写入失败 | 误触发比例、关联稳定性、合格照片与任务完成判定 |
| 地图增长、YOLO 同时推理、CPU/GPU 高负载 | 内存/通信量、积分与规划 p50/p95/p99、控制周期尾延迟、有效计划产出率 |

核心指标应至少包括：

- **探索效率：**可达场景体积的有效观测覆盖率、达到预定覆盖比例的时间、路程、重复访问率。评估用真值只进入评估器，不提供给导航器；封闭不可达空间不能简单计入“必须探索”的分母。
- **巡检质量：**满足任务成像要求的表面覆盖率、互补视角、无效照片率。不能用探索体素覆盖或文件数量替代表面覆盖。
- **运行安全：**碰撞、未知空间侵入、未满足停止裕量的指令次数；测试目标为零，同时报告测试范围。有限次零事故不等于形式化安全保证。
- **地图质量：**与真值对齐后的墙厚、重影体积、薄障碍召回、错误空闲率，以及坐标重置后错误跨 epoch 积分次数。
- **可实时性：**积分/发布/规划/控制延迟分布、峰值内存、计划作废率与有效计划间隔。根据实测停止能力设运行时限，而非先随意指定一个毫秒数。
- **预测可信度：**预测与实际信息增益、任务耗时、返航余量的偏差；有独立真值时评估定位误差与协方差校准程度。

有针对性的验证包括：DDA 与独立几何参考对照；地图增量与全量状态对照；故障时序重放；连续曲线机体扫掠体检查；全链路仿真；最后在已标定、受控室内逐步扩大实机范围。已有单元/对照测试应继续运行，但不能代替这些系统指标。

### 9.3 定位感知的后续条件

R14 将视觉特征可观测性用于前沿与偏航规划，并给出弱纹理室内试验；这说明定位质量可以成为探索目标的一部分，但其传感器基础是 VIO。[R14](https://arxiv.org/abs/2603.15605)

本项目优先采集逐锚距离、时间戳、残差、可用锚数、几何条件、丢包和独立位置参考，建立与实际空间有关的 UWB 质量估计。存在实测质量地图后，再替换当前“方差随距离增长”的启发式。若真正加入 VIO，再评估特征数/分布、跟踪寿命和偏航对定位的影响；不能仅接一个视觉特征分数就声称改进了 UWB 定位。

学习式 NLOS、因子图、联合定位—规划可以继续研究，但需要符合此前顺序：**先测距与质量评估，再改善融合；数据与所需传感器齐备后再评估学习或图优化。**

### 9.4 暂不优先采用的方向

暂不整体替换为端到端强化学习；不把 NeRF/3D Gaussian Splatting 的视觉效果当作已验证的碰撞地图；不因高性能论文存在就先上多机协同或追求高速；不通过单纯增大点数上限、更新频率、候选数解决所有问题。它们可以成为后续对照，但当前测量质量、状态可靠性和可停止轨迹更直接决定室内任务是否可用。
